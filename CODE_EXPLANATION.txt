1. HIGH-LEVEL ARCHITECTURE & HOW FILES RELATE TO EACH OTHER
================================================================================
The application is structured into four distinct, loosely coupled layers:

[ Layer 1: Configuration & Environment ]
  `src/config.py`: Centralizes filesystem directory paths (data, models, outputs)
  and baseline constants (thresholds, frequencies). It guarantees directories
  exist on disk so downstream modules never encounter "Directory Not Found" errors.

               │
               ▼
[ Layer 2: Ingestion, Standardization & Data Quality ]
  `src/cleaning.py`: The data gatekeeper. Raw Excel/CSV industrial logs contain
  over 100 channels with timestamp drift (e.g., 00:00:31, 01:00:15) and packet drops.
  This module dynamically discovers timestamp and metric columns, reindexes
  timestamps to an unbroken hourly grid (8,760 hours/year), interpolates minor gaps,
  and outputs a cleaned DataFrame (`clean_df`) plus an audit summary (`summary`).

               │
               ▼
[ Layer 3: Electrical Event Detection & Engineering Analytics ]
  `src/detector.py`: Takes `clean_df` from `cleaning.py`. Scans across active
  power, voltage, power factor (PF), and total harmonic distortion (THD). It groups
  contiguous hourly violations into discrete events (Outages, Load Trips, Poor PF,
  High THD), computes severity ("Critical", "High", "Medium", "Low"), and returns
  a structured event log (`events_df`).

  `src/reporter.py`: Takes `clean_df` and `summary`. Computes mathematical rollups
  (Daily Summary, Monthly Summary) distinguishing Instantaneous Power (Watts)
  from Accumulated Energy (Wh). Converts monthly metrics into a formatted
  executive PDF report via ReportLab in-memory.

               │
               ▼
[ Layer 4: Interactive Dashboard & UI Presentation ]
  `ui/app.py`: The user-facing coordinator. Built with Streamlit and Plotly.
  When a user uploads an Excel file, `app.py`:
    1. Passes raw data to `cleaning.py` to generate `clean_df`.
    2. Passes `clean_df` to `detector.py` to generate `events_df`.
    3. Passes `clean_df` to `reporter.py` to produce CSV/PDF download payloads.
    4. Renders responsive KPI metric cards, time series load curves with event
       markers, interactive filterable event tables, and direct report downloads.

Function 4: calculate_max_continuous_consecutive(condition_series: pd.Series) -> int
------------------------------------------------------------------------------------
Goal: Vectorized calculation of the longest unbroken run of `True` values (e.g., longest continuous blackout).

Line-by-Line Breakdown:

Line 138:     `blocks = (~condition_series).cumsum()[condition_series]`

Function 2: calculate_severity(event_type: str, duration_hours: int, metrics: Dict) -> str
-------------------------------------------------------------------------------------------
Goal: Assigns a standardized severity ("Critical", "High", "Medium", "Low") based on electrical engineering rules.
Line 74-80: Outage Severity:
            Duration >= 6h -> "Critical" (prolonged blackout)
            Duration >= 2h -> "High"
            Duration < 2h  -> "Medium" (short breaker trip)
Line 82-89: Load Trip Severity (>40% drop in 1 hour):
            Max drop >= 75% or duration >= 3h -> "Critical" (severe plant failure)
            Max drop >= 55% or duration >= 2h -> "High"
            Otherwise                         -> "Medium"
Line 91-100: Poor Power Factor (PF < 0.85):
            Min PF < 0.65 or duration >= 8h -> "Critical" (extreme reactive energy penalty)
            Min PF < 0.75 or duration >= 4h -> "High"
            Min PF < 0.80 or duration >= 2h -> "Medium"
            Otherwise                       -> "Low"
Line 102-111: High Harmonics (THD > 5% IEEE 519 standard):
            Max THD > 12% or duration >= 12h -> "Critical" (risk of transformer overheating/fire)
            Max THD > 8% or duration >= 6h   -> "High"
            Max THD > 6% or duration >= 3h   -> "Medium"
            Otherwise                        -> "Low"

Function 4: detect_industrial_events(df, power_col=None, voltage_col=None, pf_col=None, thd_col=None, ...) -> pd.DataFrame
---------------------------------------------------------------------------------------------------------------------------
Goal: Main event detection orchestrator. Scans for all 4 industrial event types and returns a sorted DataFrame.

Line-by-Line Breakdown:
Line 201-204: Returns empty DataFrame with predefined schema if `df` is empty.
Line 208-216: Extracts timestamps from DatetimeIndex or from a column named "timestamp".
Line 218-225: Resolves actual column names for power (`p_col`), voltage (`v_col`), power factor (`pf_channel`),
              and harmonics (`thd_channel`) using `resolve_channel()`.

Section 1: Outages (Lines 231-256)
- Evaluates `power_series <= power_threshold_zero` (default 50 Watts / 0.05 kW).
- If voltage channel exists, records voltage during the outage.
- Note: Evaluates plant power outage whenever power is zero, preserving voltage in event details so
  engineers can see if the utility grid was alive (plant trip) or dead (utility blackout).
- Passes mask to `group_consecutive_hourly_events()` and appends results.

Section 2: Load Trips / Drops (Lines 261-281)
- Calculates hourly change: `prev_power = power_series.shift(1)`.
- Calculates percentage drop: `pct_drop = ((prev_power - power_series) / prev_power) * 100`.
- Flags trip if `significant_previous` (equipment was running) AND `pct_drop >= 40%`.
- Passes mask to `group_consecutive_hourly_events()` and appends results.

Section 3: Poor Power Factor (Lines 286-303)
- Takes absolute value `pf_series = df[pf_channel].abs()` (standard practice for lagging/leading PF).
- Evaluates condition only when equipment is running: `active_load_running & (pf_series < 0.85) & (pf_series > 0.0)`.
- Passes mask to `group_consecutive_hourly_events()` and appends results.

Section 4: High Harmonics THD (Lines 308-318)
- Flags hours where `thd_series > 5.0%`.
- Passes mask to `group_consecutive_hourly_events()` and appends results.

Line 325-328: Combines all events into a single pandas DataFrame, sorts chronologically by `start_time`,
              resets index, and returns `event_df`.

To see how all files collaborate, let us trace a single telemetry reading:

1. In `ESP_Demo_Data_1Year.xlsx`:
   Row 483: `ts = 2025-01-21 03:00:06`, `watts_total = 0.0`, `vll_avg = 139004.8 V`.

2. In `src/cleaning.py`:
   - `get_column_inventory()` recognizes `ts` as datetime, `watts_total` as active power,
     and `vll_avg` as line voltage.
   - `process_and_reindex_grid()` floors the timestamp: `2025-01-21 03:00:00`.
   - The row is indexed on the 8,760-hour calendar grid.
   - Because `watts_total` is 0.0, it is not missing; it is preserved as `0.0` in `watts_total_clean`.

3. In `src/detector.py`:
   - `detect_industrial_events()` receives the cleaned row.
   - Checks power: `0.0 <= 50.0 W` -> Outage condition is TRUE.
   - Checks previous hour: `prev_power = 12,000,000 W`, drop = 100% -> Load Trip condition is TRUE.
   - `group_consecutive_hourly_events()` calculates duration = 1 hour.
   - `calculate_severity()` rates the 100% drop as "Critical" and the 1-hour shutdown as "Medium".
   - Appends two event records to `events_df`.

4. In `src/reporter.py`:
   - `generate_daily_summary()` aggregates January 21: records `min_power = 0.0 W`.
   - `generate_monthly_summary()` rolls this into January 2025 totals.
   - `generate_monthly_pdf_report()` draws January's row into the PDF report table.

5. In `ui/app.py`:
   - The Plotly chart draws the load curve dropping to 0 at `2025-01-21 03:00:00` with a red alert triangle.
   - The Anomaly tab lists the Critical Trip and Medium Outage with exact start/end times.
   - The Reports tab offers immediate download of the daily CSV, monthly CSV, and audit PDF.
